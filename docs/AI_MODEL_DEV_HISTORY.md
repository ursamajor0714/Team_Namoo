## 2. 0단계 — 왜 이 작업이 시작됐나

**목적: 출발점의 상태를 기록해 두기 위해서입니다.**

원래 이 모델은 **Google Colab(콜랩)** 에서 학습시켜 Drive 에 저장하고,
그 폴더를 `classification-api/model/latest` 로 복사해 서빙하고 있었습니다.

문제 제기는 **"학습을 어디서 돌릴 것인가"** 에서 시작했습니다.
`~/Downloads/GPU_모델학습_환경정리.txt` 에 RX 7600(Windows) vs M4(Mac) 비교 메모가
있었고, 결론은 **M4/MPS** 였습니다.

- RX 7600 은 AMD 라 CUDA 를 못 씁니다. ROCm 공식 지원 목록에도 없어 우회 세팅이 필요합니다.
- M4 의 MPS(Metal Performance Shaders) 는 PyTorch 가 공식 지원해서
  `device="mps"` 한 줄이면 됩니다.

**실제로 검증해 보니 이 결론이 맞았습니다.** 별다른 우회 설정 없이 학습이 돌았습니다.

> **용어**: MPS = 애플 실리콘의 GPU 를 파이토치가 쓰게 해주는 통로.
> NVIDIA 의 CUDA 에 해당하는 것이라고 보면 됩니다.

## 3. 1단계 (9/5) — 환경을 옮기고, 현재 상태를 처음 재봤다

### 3-1. 무엇을 만들었나

콜랩 의존을 끊고 **로컬에서 전 과정을 돌릴 수 있게** 만들었습니다.

```
1 수집   →  2 라벨링  →  3 학습  →  4 평가
```

가장 품이 많이 든 것은 **1번(수집)** 이었습니다.
`Team_Namoo_server` 의 자바 뉴스 수집 로직 5개 클래스를 파이썬으로 옮겼습니다.

| 자바 클래스 | 하는 일 |
|---|---|
| `NaverNewsApiClient` | 네이버 API 호출 |
| `ArticleTextExtractor` | 기사 본문 추출 |
| `NonPoliticalOutletFilter` | 스포츠·연예 매체 걸러내기 |
| `CollectedLinkStore` | 이미 수집한 링크 기억 |
| `NewsCollectionService` | 전체 흐름 |

**그대로 따른 것**: API 엔드포인트와 인증 헤더, 페이징 제약(한 번에 10~100건, `start` 최대 1000),
본문 지문(SHA-256)으로 통신사 재배포 기사 제거, 중복 방지 기록.

**바꾼 것**: 자바의 `readability4j` → 파이썬 `trafilatura`(같은 역할),
Jsoup 셀렉터 → BeautifulSoup + 정규식.

**새로 넣은 것**: `--max-per-outlet` (언론사별 상한).
**한 매체에 쏠린 데이터로 학습하면 그 매체의 문체를 논조로 착각합니다.**

## 4. 2단계 (9/6) — 진짜 병목은 모델이 아니라 '라벨'이었다 ★

**이 프로젝트에서 가장 중요한 발견입니다.**

### 4-1. 먼저 채점 기준을 만들었다

개선을 재려면 **변하지 않는 자**가 필요합니다.
사용자가 기사 50건을 직접 읽고 라벨을 달아 **정답셋**을 만들었습니다.

- 50건은 언론사 39곳에 분산 — 한겨레·경향·프레시안 ↔ 문화일보·뉴데일리·펜앤마이크
- **정답셋은 학습에 절대 넣지 않습니다.** 시험지를 미리 보는 것과 같기 때문입니다
- 기존에 있던 시드 40건은 사용자 지시로 정답셋에서 뺐습니다

### 4-2. 학습이 40%에서 안 올라갔다 — 원인을 추측하지 않고 쟀다

"데이터가 부족한가", "설정이 나쁜가" 를 추측하는 대신,
**정답셋 50건을 Claude 에게 다시 풀려 사람 답과 대조**했습니다.

> **일치율 56%**

**학습에 쓰는 라벨과 채점하는 라벨의 기준이 다르면, 모델 정확도의 천장이 거기서 막힙니다.**
아무리 잘 가르쳐도 **출제 기준이 다른 시험**을 보는 것과 같습니다.

### 4-3. 불일치 22건을 한 건씩 뜯어봤다

**(가) 사람 쪽이 고친 것 — 8건**

| 기사 | 수정 |
|---|---|
| 홍준표가 김승원 비판 | 진보 → **보수** (단순 오타) |
| 이재명 지지율 하락 | 진보 → **중립** |
| 이란 호르무즈 경고 (4건) | 중립 → **판단불가** |
| 역사·행사·지역개발·건보 (4건) | 중립 → **판단불가** |
| '윤석열 호위무사' 이용 사퇴 | 보수 → **진보** |

마지막 건이 가장 논의가 길었습니다. 처음에 '보수'로 본 이유는 기사에서 느껴지는
윤석열 옹호였는데, **옹호하는 것은 기사가 아니라 기사가 인용한 이용 본인의 말**이었습니다.
기자는 '호위무사'라는 조롱조 별칭을 제목에 걸고, "친분을 **과시**"라고 서술하고,
"**불법**계엄"이라 두 번 단정합니다. 매체도 주간경향입니다.
**논조는 윤석열·국민의힘을 향한 비판입니다.**

**(나) Claude 쪽이 틀린 것 — 15건 중 14건이 한 가지 원인**

> **여야 발언이 한 줄이라도 같이 실리면 '중립'으로 눙쳤다.**

정답셋의 '보수' 9건을 1차 모델이 **하나도** 못 맞힌 이유가 이것이었습니다.
학습 데이터에서 보수가 죄다 중립으로 달려 있었으니 배울 수가 없었습니다.

### 4-4. 라벨 기준을 확정했다

**진보 / 보수 — 등장 진영이 아니라 논조로 판단한다**

- 누가 등장하는가가 아니라 **기사의 무게중심이 어느 쪽 주장에 실려 있는가**
- 보수 인사가 민주당 인사를 공격하는 기사는 '보수'다
- **양측 발언이 함께 실렸다는 이유만으로 중립을 주지 않는다.**
  한쪽이 제목과 앞부분을 차지하고 다른 쪽은 한 줄 반박이면 비중이 큰 쪽으로 준다

**중립 / 판단불가 — 판단불가가 훨씬 넓다**

- **국내 정치 진영 대립이 기사의 축이 아니면 '중립'이 아니라 '판단불가'다**
  - 국제·외교·안보 (한국 정부 대응이 언급돼도 국내 여야 대립이 쟁점이 아니면)
  - 지역 개발·예산·행정·홍보 행사
  - 역사·문화, 여야가 함께한 비정치 행사, 논조 없는 제도 해설
- '중립'은 **국내 정치가 소재이면서 어느 진영도 편들지 않을 때만** 쓴다

**가장 많이 틀리는 지점**

> **기사의 입장 ≠ 기사에 등장하는 정치인의 입장.**
> "민주당 의원이 법안을 발의했다"는 **진보 기사라는 증거가 아닙니다.**
> "민주당 의원의 의혹을 보도했다"는 **보수 기사라는 증거가 아닙니다.**

### 4-6. 이 단계에서 배운 것

- **성능이 안 오르면 모델·설정을 만지기 전에 데이터 라벨부터 의심한다.**

## 5. 3단계 (9/6~7) — 기사 20,053건 수집, 17,763건 라벨링

### 5-2. 라벨링 — 유료 API 없이

**별도 Anthropic API 키를 쓰지 않았습니다.** 세션의 Claude 가 기사를 직접 읽고
판정하는 도구(`src/session_label.py`)를 만들어, 100건씩 뽑아 읽고 결과를 되돌려 저장했습니다.

- 오래된 기사부터 진행 (사용자 지시: "과거서부터하자 최근껄 가장 나중에")
- 500건 단위 36개 파트로 나눠 순차 진행
- 정답셋에 있는 제목은 자동으로 제외

**최종: 17,763건**

| 라벨 | 건수 | 비율 |
|---|---:|---:|
| 판단불가 | 8,617 | 48.5% |
| 중립 | 5,819 | 32.8% |
| 보수 | 2,064 | 11.6% |
| **진보** | **1,263** | **7.1%** |

**진보가 가장 드뭅니다. 이것이 이 프로젝트의 핵심 난점입니다.**
그냥 학습시키면 모델이 "진보는 무시하고 나머지만 맞히자"를 택합니다.

### 5-3. 파트마다 분포가 크게 튀었다 — 기준 문제가 아니라 뉴스 문제였다

작업 중 특정 구간에서 분포가 심하게 흔들려 "라벨 기준이 흔들린 것 아닌가" 걱정했습니다.
**확인해 보니 그날 뉴스가 무엇으로 채워졌는지를 반영한 것이었습니다.**

| 구간 | 무엇이 튀었나 | 그날 무슨 일이 있었나 |

| part_015~020 | **중립이 50~60%** | 여야 워크숍·연찬회, 개각, 정기국회 개막 등 **정당정치 스트레이트**가 통신사 재배포로 수십 건씩 겹침 |

**결론: 특정 파트 분포를 보고 기준을 조정하면 안 됩니다. 반드시 누적 분포로 판단해야 합니다.**

그리고 마지막 파트에서 **"진보 라벨이 적었던 것은 기준 탓이 아니라 그동안의 뉴스가
정책 발표에 쏠려 있었기 때문이며, 공방일에는 진영 라벨이 정상적으로 잡힌다"** 는 것이
확인됐습니다.

### 5-4. 라벨링 오류를 한 덩어리 잡아냈다 — 이혜훈 건 89건 정정

## 6. 4단계 (9/7) — 학습 설정 탐색: 대부분 헛수고였다

**목적: 실패한 시도를 남겨 두 번 하지 않기 위해서입니다.**

### 6-1. 학습률(learning rate) 4가지 비교 → 폐기

> **용어**: 학습률 = 한 번에 얼마나 크게 고쳐 배울지. 크면 빨리 배우지만 거칠어집니다.

같은 데이터에 학습률만 바꿔 각각 처음부터 학습했습니다.

| 학습률 | 초기 정확도 | 오답 수 | **최종 정확도** |
|---|---:|---:|---:|
| 2e-5 (0.00002) | 54.0% | 133 (26.6%) | 70.0% |
| 4e-5 | 60.0% | 67 (13.4%) | 70.0% |
| 6e-5 | 62.0% | 41 (8.2%) | 70.0% |
| 8e-5 | 62.0% | 27 (5.4%) | 72.0% |

**"6e-5, 8e-5 는 권장 범위를 넘어 무너질 것"이라던 예측은 틀렸습니다. 하나도 안 무너졌습니다.**

**그런데 얻은 것이 없었습니다.**

- 초기 학습은 좋아지고 오답이 133 → 27 건으로 줄지만,
  **오답이 준 것은 학습 데이터를 잘 외웠다는 뜻이지 실력이 늘었다는 뜻이 아닙니다**
- 최종 성적은 70 → 70 → 70 → 72% 로 제자리
- 정답셋이 50건이라 **70%와 72%는 1건 차이**. 통계적으로 같습니다

**결론: 학습률 튜닝 폐기. 4e-5 로 고정.**
(8e-5 가 1건 앞서지만 오답률 5.4% 로 가장 심하게 외우는 방향이라 위험합니다.)

### 6-2. 낮은 값에서 시작해 올려가면? → 더 나빴다

"그건 그 값으로만 돌릴 때 얘기지, 순차로 올리면 모르는 것 아니냐"는 지적에 따라
앞 회차 모델을 이어받아 학습률을 올려가며 4회차를 돌렸습니다.

| 회차 | 학습률 | 정확도 |
|---|---|---:|
| 1 | 2e-5 | 54.0% |
| 2 | 4e-5 | **68.0%** ← 정점 |
| 3 | 6e-5 | 64.0% |
| 4 | 8e-5 | 68.0% |
| 오답 재학습 후 | | **66.0%** |

**순차는 독립보다 나쁩니다** (66.0% vs 70~72%).

- **2회차에서 정점을 찍고 그 뒤로 퇴보합니다.** 계속 학습시킨다고 계속 좋아지지 않습니다
- **오답이 12건(2.4%)까지 줄었는데 성적은 최악입니다.**
  학습 데이터 500건 중 488건을 맞히니 사실상 다 외웠는데 처음 보는 기사는 더 못 맞힙니다

> **이것을 '과적합(overfitting)'이라고 합니다.** 문제집을 통째로 외운 학생이
> 모의고사는 100점인데 수능은 못 보는 상황입니다.

**진짜 원인은 학습률이 아니라 학습량이었습니다.** 순차는 4회차 × 3회독 = **12회독**으로
독립(3회독)의 4배를 학습했습니다.

**결론: 이 데이터 규모에서 3회독을 넘기면 과적합. 3회독 고정.**

### 6-3. 읽는 글자 수 512자 — 유일하게 효과가 있었던 것

> **용어**: 모델은 기사를 앞에서부터 정해진 길이만 읽습니다. 나머지는 잘립니다.

**실패 먼저.** 256자 → 512자로 올리면서 **"학습 시간이 2배 되겠지"** 하고
한 묶음에 넣는 기사 수(배치)는 16 그대로 두고 돌렸습니다.

| 관측값 | 정상이라면 |
|---|---|
| 스왑 사용량 **7.66GB / 8GB (94%)** | 거의 0 |
| 학습 프로세스 메모리 **11~16MB** | 수 GB |
| **39분 동안 1단계도 못 끝냄** | |

**예측이 틀렸습니다. 글자 수가 2배가 되면 메모리는 4배가 됩니다.**
(어텐션이라는 계산이 길이의 제곱에 비례하기 때문입니다.)
맥북 메모리를 넘겨 디스크로 밀려났고, 디스크를 들락거리느라 계산을 못 했습니다.

**배치를 16 → 8 로 줄이니 돌아갔습니다.** 그리고 재보니 효과가 있었습니다.

| | 256자 · 배치16 | **512자 · 배치8** |
|---|---:|---:|
| 소요 (465건) | **7분 11초** | 15분 25초 |
| 정확도 | 51.7% | **55.2%** |
| **진보 검출** | 32건 중 **6건** | 32건 중 **11건** |
| 보수 검출 | 32건 중 10건 | 32건 중 9건 |
| 중립 | 20/26 | 20/26 |
| 판단불가 | 24/26 | 24/26 |

**차이가 전부 진보 한 군데서 나옵니다.**
256자는 진보를 6번밖에 안 찍는데 512자는 16번 찍습니다.

> **왜냐하면 진보 성향 기사는 논조가 뒤쪽(인용문·마무리)에 드러나는
> 칼럼·인터뷰가 많습니다.** 앞부분 256자만 읽으면 근거를 못 봅니다.

**결론: 512자 · 배치 8 확정.** 전체 학습 시간이 2배 이상 늘지만
**이 프로젝트의 목적이 진영 판별**이므로 감수합니다.

### 6-4. 오답만 다시 학습시키기 → 모델이 망가졌다

"틀린 문제만 다시 풀리면 좋아지지 않을까" 해서 오답 133건만으로 재학습했습니다.

| | 1차 | **오답만 재학습** |
|---|---:|---:|
| 정확도 | 54.0% | **20.0%** |
| 중립 F1 | 0.30 | **0.00** |
| 판단불가 F1 | 0.82 | **0.00** |

**정확도가 54% → 20% 로 무너졌습니다.**

원인은 오답의 구성입니다. 틀린 133건 중 **보수 69 + 진보 37 = 106건(80%)** 이었습니다.
1차 모델이 진영을 아예 안 찍었으니 그것들만 죄다 틀린 게 당연하고,
그 목록만 다시 학습시키니 모델이 **"세상은 진보 아니면 보수"** 로 뒤집혔습니다.
중립·판단불가는 **한 건도** 예측하지 않게 됐습니다.

> **오답노트만 보고 원래 문제집을 안 보면 나머지를 까먹습니다.**

**해결: 원본 500건에 오답 133건을 얹어 633건으로 재학습.**
오답에 자연스럽게 2배 가중이 걸립니다.

| | 1차 | 오답만 | **원본+오답** |
|---|---:|---:|---:|
| 정확도 | 54.0% | 20.0% | **70.0%** |
| 진보 F1 | 0.00 | 0.08 | **0.40** |
| 보수 F1 | 0.00 | 0.44 | **0.62** |
| 판단불가 F1 | 0.82 | 0.00 | **0.91** |

**1차에는 두 라벨만 찍었는데 재학습 뒤 네 라벨을 모두 찍습니다.**

*(다만 이 장치는 나중에 8단계에서 끄게 됩니다. 7-3 참조.)*

### 6-5. 정답셋을 50건 → 116건으로 키웠다

50건에는 문제가 둘 있었습니다.

1. **판단불가가 26건(52%)** 이라 편향돼 있었습니다.
   **아무 생각 없이 판단불가만 찍어도 정확도 52%** 가 나옵니다.
2. **너무 작아서 70%와 72%가 1건 차이**였습니다. 어떤 변화도 유의미하다고 말할 수 없었습니다.

사용자가 66건을 추가로 직접 검수해 **116건**으로 확정했습니다.

| 라벨 | 기존 | 신규 | **합계** |
|---|---:|---:|---:|
| 진보 | 8 | 24 | **32** |
| 보수 | 9 | 23 | **32** |
| 중립 | 7 | 19 | **26** |
| 판단불가 | 26 | 0 | **26** |
| 합계 | 50 | 66 | **116** |

> **정답셋은 사용자가 직접 만듭니다.** 세션이 라벨까지 붙여 채우면
> 정답셋이 **"모델이 세션의 라벨을 얼마나 잘 따라하나"** 를 재는 자로 바뀝니다.

**중요: 이 시점 이후의 수치는 이전 수치와 직접 비교할 수 없습니다.** 자가 바뀌었습니다.

## 7. 5단계 (9/7) — 정확도 대신 쓸 점수판

**목적: 정확도라는 지표 자체에 함정이 있었습니다.**

### 7-1. 왜 정확도로는 안 되나

데이터의 **48.5%가 판단불가**입니다.
그래서 **"전부 판단불가로 찍기"만 해도 정확도가 절반 가까이 나옵니다.**

실제로 정답셋 50건 시절 그 요령의 정확도가 52% 였고,
part_001 1차 모델이 받은 54% 와 **사실상 같은 점수**였습니다.

**즉 정확도는 "아무것도 안 배운 모델"과 "조금 배운 모델"을 구분하지 못합니다.**

### 7-2. 상벌 점수판

드문 라벨을 맞히면 크게 쳐주고 놓치면 크게 깎습니다.
**배점을 손으로 정하지 않고 라벨 희소도(드문 정도)에서 자동으로 유도**합니다.

| 역할 | 현재 그 자리 | 비율 | 맞히면 | 틀리면 |
|---|---|---:|---:|---:|
| **소수진영** | 진보 | 7.1% | **+3.00** | −3.00 |
| **다수진영** | 보수 | 11.6% | +1.84 | −1.84 |
| 중립 | | 32.8% | +0.65 | −0.65 |
| 판단불가 | | 48.5% | +0.44 | **−2.20** |

설계 의도가 셋 담겨 있습니다.

1. **판단불가만 벌점이 보상의 5배입니다.** 중립↔판단불가 혼동은 가볍게 처리하면서
   "판단불가로 밀기" 요령은 막기 위한 비대칭입니다.
2. **어느 진영이 소수인지 못 박지 않습니다.** 시기마다 뒤집힙니다
   (2026-06~07 은 진보가 더 많았고 2026-09 는 보수가 3.6배 많았습니다).
   코드가 데이터에서 매번 계산합니다.
3. **만점이 정확히 100점이 되도록 환산**합니다.

### 7-3. 요령을 부리면 이렇게 됩니다

| 전략 | 점수 |
|---|---:|
| 다 맞히기 | **+100.0** |
| 전부 소수진영(진보)으로 밀기 | −20.2 |
| 전부 다수진영(보수)으로 밀기 | −60.7 |
| 전부 판단불가로 밀기 | −87.5 |
| 전부 중립으로 밀기 | −106.5 |

**0점 근처는 "괜찮음"이 아니라 "요령 수준"으로 읽어야 합니다.**

### 7-4. 실패 기록 — 첫 점수판에는 구멍이 있었다

처음 만든 점수판(v1)은 소수진영 +2, 다수진영 +1, 중립 +0.5, 판단불가 +0.1 이었습니다.
그런데 **"전부 진보로 밀기"가 +5.4점으로 0점을 넘겼습니다.**

정답셋에 라벨이 고르게 들어가는데 진보 보상만 2배라 생긴 구멍이었습니다.
배점을 희소도에서 유도하도록 고치니(v2) **−20.2 로 막혔습니다.**

> **더 중요한 교훈: 점수판이 바뀌면 그 점수로 내린 판단도 전부 다시 봐야 합니다.**
> v1 에서 "part_005 는 재학습이 해로웠다(−6.8)"고 결론냈는데
> v2 로 다시 계산하니 **+5.0 으로 부호가 뒤집혔습니다.**
> 재학습 규칙·임계값·폐기 결정이 전부 **틀린 자 위에서** 내려진 것들이었습니다.

## 8. 6단계 (9/7~8) — 채점 기준과 학습 기준이 20배 어긋나 있었다 ★최대 개선

### 8-1. 무엇이 어긋나 있었나

목표는 **점수 최대화**인데, 학습 중요도를 손으로 `2, 0.5, 1, 0.1` 로 정해 두고
채점은 다른 배점으로 하고 있었습니다.

| 라벨 | 채점에서 이 라벨 하나에 걸린 점수 | 학습에서 준 중요도 | 어긋난 정도 |
|---|---:|---:|---:|
| 진보 | 6.00 | 2.0 | 2.3배 |
| 보수 | 3.68 | 1.0 | 2.8배 |
| 중립 | 1.30 | 0.5 | 2.0배 |
| **판단불가** | **2.64** | **0.1** | **20.3배** |

판단불가는 보상(0.44)은 작지만 **벌점(−2.20)이 커서** 한 건에 걸린 점수가 중립의 2배입니다.
그런데 학습에서는 **"거의 신경 쓰지 마라"** 고 가르쳤습니다.

> **시험에는 나오는데 공부는 하지 말라고 한 셈입니다.**

**결과: 모델이 시키는 대로 판단불가를 버렸고 검출률이 0.92 → 0.27 로 무너졌습니다.**

### 8-2. 어떻게 고쳤나

학습 중요도를 **점수판에서 자동으로 유도**하도록 연결했습니다.
한 건에 걸린 **점수 진폭(보상 − 벌점)에 비례**하게 두면 됩니다.

| 라벨 | 진폭 | **학습 중요도** |
|---|---:|---:|
| 진보 | 6.00 | **4.62** |
| 보수 | 3.68 | **2.83** |
| 판단불가 | 2.64 | **2.03** |
| 중립 | 1.30 | **1.00** |

**점수판을 바꾸면 학습 중요도도 자동으로 따라갑니다. 둘을 따로 관리하지 않습니다.**

### 8-3. 결과

| | 손으로 정한 중요도 | **점수판에서 유도** |
|---|---:|---:|
| 점수 | −21.9 | **+6.1** |
| 정확도 | 44.0% | **54.3%** |

**점수와 정확도가 같이 올랐습니다.**
"점수를 올리면 정확도는 떨어질 수 있다"던 예측은 틀렸습니다.
기존 설정이 워낙 어긋나 있어서 고치니 둘 다 좋아졌습니다.

### 8-4. 곁다리로 발견한 코드 버그 — 이름이 곧 설계다

"소수/다수 진영을 데이터에서 계산하겠다"고 해놓고 계산 함수를 만든 뒤
**값을 `"진보"` 라고 박아 넣었습니다. 함수는 있는데 아무도 부르지 않았습니다.**

원인은 말버릇이었습니다. 머릿속에서 **"진보 가중치"** 라고 부르고 있었기 때문에
코드도 진보로 굳었습니다. **"소수진영 가중치"라고 불렀다면
"그럼 소수진영이 누군지는 어떻게 정하지?"가 자연스럽게 따라왔을 것입니다.**

> **교훈: 시기·데이터에 따라 바뀌는 것을 고정 이름으로 부르지 않습니다.**
> "진보 3점"이 아니라 **"소수진영(현재는 진보) 3점"** 이라고 말합니다.

## 9. 7단계 (9/8) — 파트별 학습이 애초에 틀린 실험이었다

### 9-1. 무엇을 하고 있었나

기사 17,763건을 **500건짜리 36개 파트로 나눠** 하나씩 학습시키며
"어느 시기 데이터가 진영 판별에 쓸모 있나"를 비교하고 있었습니다.

### 9-2. 문제 ① — 파트마다 한쪽 진영만 배운다

| 파트 | 학습 데이터의 진보/보수 | 진보라고 답한 횟수 | 보수라고 답한 횟수 | 보수 검출률 |
|---|---|---:|---:|---:|
| part_003 | 22 / 44 | 8 | **29** | 0.63 |
| part_004 | 60 / 31 | **51** | **1** | 0.03 |
| part_007 | 78 / 49 | 24 | **1** | **0.03** |

part_007 은 **보수 정밀도가 1.00 인데 검출률이 0.03** 입니다.
**"보수라고 한 번 말했고 그건 맞았다"는 뜻이지 보수를 아는 것이 아닙니다.**

**500건으로는 네 라벨을 다 배우지 못하고 매번 다른 것을 포기합니다.**

> **그래서 파트 점수는 "설정이 좋아졌나"가 아니라
> "그 주 뉴스가 어느 진영이었나"를 재고 있었습니다.**
> **파트끼리 점수를 비교하는 것 자체가 성립하지 않습니다.**

이것이 뼈아픈 이유는, **그때까지의 모든 튜닝(학습률 스윕, 재학습 규칙, 자동 임계값)이
이 못 믿을 자 위에서 내려진 판단**이었기 때문입니다.

### 9-3. 문제 ② — 안전장치가 세 번 다 실패했다

오답 재학습(6-4)이 **3번 연속으로 성적을 깎았습니다.**
그런데 그걸 막으라고 만든 규칙이 **3번 다 통과시켰습니다.**

| 파트 | 1단계 | 재학습 후 | 손해 | 학습데이터 정답률 | 정답셋 정확도 |
|---|---:|---:|---:|---|---|
| part_005 | **+6.1** | −21.3 | −27.4 | 0.63 → **0.88** | 0.543 → 0.509 |
| part_006 | **−15.3** | −24.2 | −8.9 | 0.78 → **0.94** | 0.517 → 0.517 |
| part_007 | **−34.1** | −45.4 | −11.3 | 0.82 → **0.92** | 0.483 → 0.440 |

**자기가 본 문제는 훨씬 잘 푸는데 처음 보는 기사는 더 못 맞힙니다.** 전형적인 과적합입니다.

**원인은 버그 두 개였습니다.**

**(가) 옛 설정 기록으로 기준값을 계산했다.**
규칙의 기준값을 "그때까지 쌓인 실측"으로 자동 계산하게 만들었는데,
**설정 세대를 구분하지 않고 섞었습니다.** 옛 중요도(`2,0.5,1,0.1`)로 돌린 기록과
새 중요도(`4.62,1.0,2.83,2.03`)로 돌린 기록이 한 통에 들어갔습니다.

> **다른 자로 잰 눈금을 새 저울에 붙인 셈입니다.**

고치니 기준값이 정직해졌습니다.

```
수정 전 → ±34%p  ("실측 12개(이득 7 / 손해 5)")     ← 세대를 섞은 값
수정 후 → 기본값 유지 ("현재 세대 표본 3개로 부족")   ← 옳은 답
```

**(나) 편차의 "크기"만 보고 "방향"을 버렸다.**
규칙이 "오답 분포가 원본과 얼마나 다른가"만 봤습니다.
**어느 라벨 쪽으로 치우쳤는지는 계산해 놓고 쓰지 않았습니다.**
앞선 분석에서 **방향이 결정적**이라고 밝혀 놓고 구현에 넣지 않은 것입니다.
(8-4 의 "함수 만들어놓고 안 부름"과 같은 유형의 실수입니다.)

**다만 방향 규칙으로 고쳐도 안 됐습니다.** 옛 설정에서 잘 맞던 신호가 새 설정에서 깨집니다.

| 파트(설정) | 오답이 진영 쪽으로 치우친 정도 | 실제 이득 |
|---|---:|---:|
| part_003 (옛 설정) | +54.4%p | **+39.8** |
| part_007 (**새 설정**) | +30.1%p | **−11.3** |
| part_005 (**새 설정**) | +0.9%p | **−27.4** |

이유는 분명합니다. **옛 설정은 진영 중요도가 낮아(진보 2.0) 진영이 굶주려 있어
오답 보충이 약이었습니다. 새 설정은 이미 진보에 4.62를 걸어 충분히 먹이므로
더 얹으면 과적합만 남습니다.**

> **결론: 기준값을 고칠 문제가 아니라 끌 문제였습니다.**

### 9-4. 그 밖에 훑어본 것 — 데이터·코드 감사

"다른 문제는 없나" 확인하기 위해 전체를 훑었습니다. **치명적인 것은 없었습니다.**

| 실수 | 교훈 |
|---|---|
| 오답만으로 재학습해 모델을 망가뜨렸다 (54%→20%) | 오답 재학습은 **반드시 원본을 섞는다** |
| 512자를 권했다가 39분을 날렸다 | 길이를 늘리면 **메모리는 제곱으로** 는다. 배치를 그만큼 줄이고, **띄운 뒤 1~2분 안에 확인**한다 |
| 학습 중요도와 채점 배점이 20배 어긋나 있었다 | **중요도를 손으로 정하지 않는다.** 채점 기준에서 유도한다 |
| 점수판이 틀리자 그 위 판단이 전부 틀렸다 | 점수판을 바꾸면 **그 점수로 내린 판단을 전부 다시 확인**한다 |
| 근거 없이 예측하고 세 번 틀렸다 | **7분이면 재볼 수 있는 것을 추측으로 말하지 않는다** |
| 병목을 확인하지 않고 자원 탓을 했다 | 느리면 **무엇이 병목인지 먼저 재고** 손댄다 |
| 부분만 재고 전체를 단정했다 ("20% 빨라짐" → 실제 7%) | 부분 측정값을 전체에 그대로 곱하지 않는다. **고정 비용**을 함께 본다 |
| 소요 시간을 22% 빗맞혔다 (2.8시간 예상 → 3시간 25분) | 위와 같은 실수의 재발. **1회독이 끝난 시점에 다시 잡는다** |

### 코드에서

| 실수 | 교훈 |
|---|---|
| 함수를 만들어놓고 연결하지 않았다 | **역할로 부른다.** "진보 3점"이 아니라 "소수진영(현재 진보) 3점". 그리고 **실제로 호출되는지 확인**한다 |
| 자동 기준값이 반대 증거를 빼서 엉뚱한 답을 냈다 | 자동 튜닝은 **양쪽 증거가 다 있어야** 성립한다. 한쪽뿐이면 계산을 거부하고 기본값을 쓴다 |
| 이전 학습이 도는데 다음을 시작했다 (2회) | 메모리 경합. **한 번에 하나만.** 스크립트로 순차 실행을 보장한다 |
| 진단 기준이 느슨해 실제 문제를 놓쳤다 | 절대 기준만으로 부족하다. **직전 대비 하락(퇴행)** 도 함께 본다 |
| 결정해 놓고 실행할 도구를 안 만들었다 | 다음 단계를 문서에 쓸 때 **실행 명령을 함께 적는다** |
| 설정을 못 읽으면 조용히 기본값으로 갔다 | **조용한 폴백이 가장 나쁘다.** 반드시 경고를 낸다 |
| 몇 시간짜리 작업의 진행률을 볼 수 없게 만들었다 | 오래 걸리는 작업은 **한 줄씩 흘려보낸다** |
| MPS 학습을 "멈췄다"고 오진했다 | **GPU 사용률로 확인한다.** 프로세스 메모리로 판단하지 않는다 |

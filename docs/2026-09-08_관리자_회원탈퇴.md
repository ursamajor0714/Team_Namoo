# 관리자 회원 탈퇴 (DB 실제 삭제)

작성일: 2026-09-08
관련 모듈: `Team_Namoo_server`(admin, board, ad), `Team_Namoo_Front`(관리자 콘솔 회원관리)

---

## 1. 무엇을 만들었나

관리자 콘솔 **회원관리 → 회원 상세 모달**에서 그 회원을 탈퇴시킬 수 있습니다.
기존의 '정지(SUSPENDED)'와 달리 **회원 행을 DB 에서 실제로 지웁니다. 되돌릴 수 없습니다.**

`DELETE /api/admin/members/{id}` — 관리자 세션 필요(그 외 403).

## 2. 참조 데이터를 어떻게 처리하는가

회원을 참조하는 테이블이 5곳이라 그냥 지우면 외래키 제약에 걸립니다. 다음 순서로 정리한 뒤 지웁니다.

| 참조 | 컬럼 NULL 허용 | 처리 |
|---|---|---|
| 추천/비추천 `post_votes` | 불가 | **삭제**하고 그만큼 글의 추천/비추천 수를 되돌린다 |
| 신고 `reports` (그가 신고자인 건) | 불가 | **삭제** (신고자 컬럼이 NOT NULL 이라 남길 수 없음) |
| 광고 `ads.created_by` | 가능 | 광고는 **남기고** 등록자 연결만 끊음 |
| 게시글 `posts.author_member_id` | 가능 | 글은 **남기고** 작성자 연결을 끊고 표시명을 `탈퇴한 회원` 으로 |
| 댓글 `comments.author_member_id` | 가능 | 위와 동일 |

**글·댓글을 남기는 이유**: 지우면 글타래에 구멍이 생기고 다른 사람 댓글이 맥락을 잃습니다.
개인정보에 해당하는 회원 행과 닉네임 표시는 사라지므로 탈퇴의 목적은 달성됩니다.

**추천수를 되돌리는 이유**: `posts.likes` 는 집계값을 컬럼에 들고 있어서, 추천 기록만 지우면
숫자가 실제 추천 수와 어긋난 채 남습니다.

## 3. 막아둔 것

- **자기 자신** 탈퇴 불가 — "자기 자신은 탈퇴시킬 수 없습니다."
- **관리자·슈퍼관리자 계정** 탈퇴 불가 — "관리자 계정은 탈퇴시킬 수 없습니다. 먼저 권한을 회원으로 되돌려주세요."
  (실수로 관리자를 날리는 것을 막기 위해 권한 강등을 한 단계 거치게 함)
- 관리자가 아니면 403 (기존 `AdminAuthInterceptor`)

프론트도 `member.role === 'USER'` 일 때만 탈퇴 버튼을 그리고, 누르면 **모달 안에서 한 번 더 확인**을 받습니다.

## 4. 검증 결과

로컬 H2(docker 프로필)에서 관리자 계정과 일반 회원으로 실제 요청을 태워 확인했습니다.
탈퇴 대상 회원에게 글·댓글·추천·신고를 모두 남긴 뒤 삭제했습니다.

| 시나리오 | 결과 |
|---|---|
| 일반 회원이 탈퇴 API 호출 | 403 |
| 관리자가 자기 자신 탈퇴 | 400 "자기 자신은 탈퇴시킬 수 없습니다." |
| 관리자 계정 탈퇴 시도 | 400 "관리자 계정은 탈퇴시킬 수 없습니다…" |
| 관리자가 일반회원 탈퇴 | 200 |
| 탈퇴 후 회원 상세 조회 | 400 "존재하지 않는 회원입니다." (DB 에서 사라짐) |
| 탈퇴 후 그 회원 로그인 | 400 "존재하지 않는 아이디입니다." |
| 그가 쓴 글 | 남아 있고 작성자 = `탈퇴한 회원` |
| 그가 쓴 댓글 | 남아 있고 작성자 = `탈퇴한 회원` |
| 글 추천수 | 1 → 0 (추천 기록 삭제분 반영) |
| 그가 넣은 신고 | 0건 (삭제됨) |

프론트 `npm run lint` 무경고, `npm run build` 성공.

## 5. 남은 것 / 알아둘 것

- **되돌릴 수 없습니다.** 실수로 지우면 복구 경로가 없습니다. 운영에서 쓰기 전에
  정지(SUSPENDED)로 충분한 상황인지 한 번 더 생각하는 편이 좋습니다.
- 탈퇴한 회원이 로그인 중이었다면 세션은 남지만 다음 요청에서 회원 조회에 실패해 자연히 끊깁니다.
- 화면에서 직접 눌러보는 확인은 아직입니다(API 레벨만 검증).

4. Spring 을 RDS 에 붙이는 법 - 코드 수정 불필요, 실행 환경변수만
--------------------------------------------------------------------

  application.properties 는 로컬 H2 로 하드코딩돼 있지만 Spring 이 환경변수를
  properties 보다 우선하므로, systemd 유닛의 EnvironmentFile 로 아래를 주면
  그대로 덮어써진다. (실제 파일은 EC2 의 ~/app/namoo-spring.env, git 미포함)

  (실제 값이 채워진 파일은 EC2 의 ~/app/namoo-spring.env 에만 있다.
   아래는 키 목록만 - 값은 커밋 금지)

    SPRING_DATASOURCE_URL=jdbc:mysql://namoo-db.cjkcywue246k.ap-northeast-2.rds.amazonaws.com:3306/teamnamoo
    SPRING_DATASOURCE_USERNAME=admin
    SPRING_DATASOURCE_PASSWORD          = (RDS 마스터 암호, 사용자 메모장)
    SPRING_DATASOURCE_DRIVER_CLASS_NAME=com.mysql.cj.jdbc.Driver
    SPRING_JPA_HIBERNATE_DDL_AUTO=update   (없으면 MySQL 은 테이블 생성 안 함!)
    SPRING_H2_CONSOLE_ENABLED=false
    NAVER_CLIENT_ID / NAVER_CLIENT_SECRET  = (기존 키 그대로. git 히스토리에 노출돼 있음)
    SPRING_MAIL_USERNAME=jyrp3026@gmail.com
    SPRING_MAIL_PASSWORD                = (Gmail 앱 비밀번호, 사용자 메모장)
    CLASSIFICATION_MODEL_BASE_URL=http://43.202.134.21:8000
    SERVER_FORWARD_HEADERS_STRATEGY=framework           (Caddy 뒤 https 인식)
    SERVER_SERVLET_SESSION_COOKIE_SAME_SITE=none        (크로스오리진 쿠키)
    SERVER_SERVLET_SESSION_COOKIE_SECURE=true

  data.sql (parties 시드) 는 MySQL 호환됨. ddl-auto=update +
  defer-datasource-initialization=true 로 테이블 생성 후 실행.
  주의: parties.name UNIQUE 없으면 재시작마다 시드 중복 INSERT.

8. 오류 수정 시 먼저 볼 것 (알려진 지뢰)
--------------------------------------------------------------------

[프론트에서 API 호출이 전부 실패 / CORS 에러]
  - Amplify env VITE_API_BASE_URL 이 https://15-165-118-162.sslip.io 맞나?
    빌드 시점 주입이라 값 바꾸면 반드시 재배포(redeploy).
  - 백엔드가 http 면 브라우저가 혼합콘텐츠 차단 → 반드시 https (Caddy).
  - CorsConfig 기본값에 Amplify origin 있음. 커스텀 도메인 붙이면
    APP_CORS_ALLOWED_ORIGINS 에 추가.

[로그인이 되는데 새로고침하면 풀림 / 로그인 자체가 안 됨]
  - JSESSIONID 쿠키가 SameSite=None; Secure 여야 크로스오리진 유지됨.
    namoo-spring.env 의 SERVER_SERVLET_SESSION_COOKIE_* 3개 확인.
  - SERVER_FORWARD_HEADERS_STRATEGY=framework 없으면 Spring 이 자기가 http 인
    줄 알고 Secure 쿠키를 안 만듦 (Caddy 가 X-Forwarded-Proto 는 보냄).
  - 브라우저 개발자도구 > Application > Cookies 에서 JSESSIONID 속성 확인.

[뉴스가 안 나옴 / 500]
  - NewsCacheRefreshScheduler 가 아직 안 돌았으면 캐시가 비어있음
    (기동 직후 1회 + 30분마다). journalctl 에서 "뉴스 캐시 갱신 완료" 확인.
  - MySQL 테이블 생성 실패 → CLOB 버그 재발 가능성 (엔티티에 columnDefinition
    "CLOB" 새로 들어왔는지). journalctl 에서 "GenerationTarget" 검색.
  - NAVER API 일별 쿼터. 429 뜨면 고장 아니라 쿼터.

[분류 태그가 안 나옴 (leaning=null)]
  - 팀원 분류서버(43.202.134.21:8000) 살아있나:
    EC2 에서 curl -m 45 http://43.202.134.21:8000/health
  - 팀원 SG 8000 인바운드에 15.165.118.162/32 있나.
  - 콜드스타트 20~40초. ClassificationModelClient callTimeout 90초.
  - 앱은 안 죽음 - leaning=null 반환, 프론트가 태그만 숨김.

[Amplify 빌드 실패]
  - 앱루트 Team_Namoo_Front 로 잡혔나 (AMPLIFY_MONOREPO_APP_ROOT).
  - Node 버전 (vite 8 = Node 18+). npm ci 는 package-lock.json 필요
    (Team_Namoo_Front/package-lock.json 있음).

[Spring 이 안 뜸 / 메모리]
  - t3.micro 1GB. -Xmx512m + swap 2GB 로 버팀. free -m 확인.
  - namoo-spring.env 문법: systemd EnvironmentFile 은 셸 아님. 따옴표/공백 주의.
  - DB 접속 실패면 journalctl 에 HikariPool / Access denied / Unknown database.

[비용]
  - 탄력적 IP: 인스턴스 중지 상태로 두면 과금. 켜놓기.
  - RDS 스토리지 자동조정 OFF 확인. EBS 30GB.
  - EC2/RDS 다른 AZ 라 크로스 AZ 전송요금 소액 발생 (이 규모엔 무시).
  - 결제 경보는 us-east-1 CloudWatch.

# 게시글·댓글 수정/삭제 프론트 연동

작성일: 2026-09-08
관련 모듈: `Team_Namoo_Front`, `Team_Namoo_server`
관련 커밋: 백엔드 API `0da0cb7`(9/7), 이번 연동 작업

---

## 1. 무엇이 문제였나

**백엔드 API 는 9/7 에 이미 만들어져 있었는데 프론트가 그 API 를 호출하지 않고 있었습니다.**

- `Team_Namoo_Front/src/api/boardApi.js` 에 수정/삭제 호출 함수 자체가 없었음
- `Team_Namoo_Front/src/pages/PostDetailPage.jsx` 의 수정·삭제 버튼은
  `showUnavailable('수정')` — "백엔드 API 가 아직 없어 동작하지 않습니다" 안내만 띄우는 자리표시자
- 같은 파일 주석도 "스크랩/수정/삭제는 아직 백엔드 API 가 없어 안내만 띄운다" 로 남아 있었음

서버 API 가 그 프론트 코드보다 **나중에** 들어왔는데, 프론트를 다시 연결하지 않아 생긴 일입니다.
같은 실수를 막기 위해 `RULES.txt` 하단 오답노트 4번에 기록했습니다.

## 2. 백엔드에 추가한 것 — 소유자 표시(`mine`)

수정/삭제 버튼은 **본인 글에만** 보여야 하는데, 프론트가 "이 글이 내 글인지" 알 방법이 없었습니다.
응답에 작성자 이름(`author`)만 있었고, 익명 글은 작성자 이름이 전부 "익명" 이라
닉네임 비교로는 남의 익명 글까지 내 글로 오인할 수 있었습니다.

그래서 응답에 **`mine`(보고 있는 사람이 작성자 본인인가)** 을 추가했습니다.

| 파일 | 변경 |
|---|---|
| `PostDetailResponse.java` | `mine` 필드 추가, 생성자가 조회자 `viewerMemberId` 를 받음 |
| `CommentResponse.java` | 동일 |
| `PostService.java` | `getDetail`/`getComments` 가 조회자 id 를 받아 `mine` 계산 |
| `PostController.java` | 조회 API 에서도 세션의 `loginMemberId` 를 넘김 (비로그인이면 null → `mine=false`) |

수정·삭제 엔드포인트 자체는 9/7 것을 그대로 씁니다(새로 만들지 않음).

## 3. 프론트에 추가한 것

**`src/api/boardApi.js`** — 호출 함수 4개

- `updatePost(postId, {title, content})` → `PUT /api/posts/{id}`
- `deletePost(postId)` → `DELETE /api/posts/{id}`
- `updateComment(commentId, content)` → `PUT /api/comments/{id}`
- `deleteComment(commentId)` → `DELETE /api/comments/{id}`

**`src/pages/PostDetailPage.jsx`**

- 글: `post.mine` 이 true 일 때만 수정/삭제 버튼 노출. 수정을 누르면 제목·본문이 **그 자리에서 입력폼**으로 바뀌고 저장/취소를 고를 수 있음
- 댓글: `c.mine` 인 댓글에만 수정/삭제 버튼. 수정은 해당 댓글만 입력폼으로 전환
- 삭제: 네이티브 `confirm()` 대신 공용 `Modal` 을 쓴 확인 창(`ConfirmDeleteModal`)을 거침.
  글 삭제 후에는 목록으로 이동, 댓글 삭제 후에는 목록만 다시 읽음
- 자리표시자였던 `showUnavailable('수정'/'삭제')` 제거 (스크랩은 아직 API 가 없어 그대로 둠)

## 4. 검증 결과

로컬에서 서버를 H2 로 띄우고 회원 2명(A=테스터일, B=테스터둘)으로 실제 요청을 태워 확인했습니다.

| 시나리오 | 결과 |
|---|---|
| A가 자기 글 조회 | `mine=true` |
| B(남)가 같은 글 조회 | `mine=false` |
| 비로그인 조회 | `mine=false` |
| A가 자기 글 수정 (PUT) | 200, 제목·내용 반영 확인 |
| B가 남의 글 수정 시도 | 400 "본인이 작성한 글/댓글만 수정·삭제할 수 있습니다." |
| 비로그인 삭제 시도 | 401 "로그인이 필요합니다." |
| A가 자기 댓글 수정 | 200, 내용 반영 |
| A가 자기 댓글 삭제 | 200, 목록에서 사라짐 |
| A가 자기 글 삭제 | 200, 이후 조회 시 "존재하지 않는 게시글입니다." |

프론트는 `npm run lint` 무경고, `npm run build` 성공.
브라우저 화면 확인은 Chrome 확장이 꺼져 있어 이번에 못 했습니다 — **화면에서 한 번 눌러보는 확인이 남아 있습니다.**

## 5. 알아둘 것

- 삭제는 **실제 삭제가 아니라 노출 상태를 `DELETED` 로 바꾸는 것**입니다(관리자 삭제와 동일). 복구 가능하고 신고 이력도 남습니다.
- 익명 글/댓글(`authorMember` 없음)은 소유자를 특정할 수 없어 **수정·삭제 대상이 아닙니다.** `mine` 도 항상 false 입니다.
- 게시판 글쓰기·댓글은 **자기가 지지 정당으로 설정한 게시판에서만** 가능합니다(기존 규칙). 검증 중 B가 국민의힘 게시판에 댓글을 못 단 것은 이 규칙 때문이며 버그가 아닙니다.

# 나무 관리자 콘솔 기획 (프론트 구축안)

- 작성일: 2026-09-03
- 담당: 프론트 (Team_Namoo_Front)
- 스택: React · Vite · React Router · Zustand · axios
- 범위: **프론트엔드만.** 서버·DB·API는 이 문서 밖이고, 미구현 기능은 화면과 버튼만 배치한 뒤 "연동 예정"으로 처리한다.
- 웹 뷰: https://claude.ai/code/artifact/f38bfb8b-c828-4bb7-abe0-4cf2b0460935

---

## 1. 작업 범위

### 이번에 만드는 것 (프론트)
- `/admin` 라우트 전체 — 레이아웃, 사이드 네비, 페이지들
- 목록·상세·폼 **화면과 컴포넌트** 전부
- 목(mock) 데이터로 표·필터·검색·페이지네이션·정렬 **클라이언트 동작**
- 로딩 / 빈 상태 / 에러 상태 UI
- 모든 액션 버튼 **배치** — 저장·삭제·정지 등

### 안 하는 것 (백엔드 담당·나중)
- DB 스키마, 테이블 설계
- 관리자 인증·권한 실제 검증
- `/api/admin/**` 엔드포인트
- 실제 데이터 저장·수정·삭제
- 뉴스 재수집·재분류 실행

> 기존 프론트가 이미 쓰는 패턴을 그대로 이어간다. `src/constants/dummyBoardPosts.js` 주석의
> "API 붙으면 이 파일을 실제 fetch로 교체" 방식을 `src/mocks/`로 확장하는 것뿐이다.

## 2. 미구현 처리 방식

데모에서 "되는 것"과 "자리만 잡은 것"이 헷갈리지 않도록 규칙을 하나로 통일한다.

### 읽기 화면 (목록·상세·통계)
- `src/mocks/*.json` 에서 데이터 로드. `src/api/adminApi.js`에 `fetchXxx()` 함수를 만들되
  지금은 목 JSON을 `Promise.resolve`로 반환 → 연동 시 이 함수 본문만 axios로 교체
- 정렬·검색·필터·페이지네이션은 목 배열 위에서 프론트가 직접 처리

### 쓰기 액션 (저장·삭제·정지·블라인드 등)
- 버튼은 실제 위치에 그대로 배치. 클릭하면 공통 `useStubAction()` → 토스트 **"백엔드 연동 예정입니다"**
  + `console.info`로 어떤 요청이 나갈지 로그
- 파괴적 액션(삭제·강제탈퇴·영구정지)은 **확인 모달까지** 구현하고, "확인" 시 토스트
- 단순 토글(노출/숨김, 고정)은 화면 상태만 낙관적으로 바꾸고 **"새로고침 시 초기화됨"** 안내 문구 표시
- 모든 스텁 컨트롤에 작은 `미구현` 뱃지(점선 테두리)

### 플래그
- `VITE_ADMIN_MOCK=true` — 목 모드. 화면 상단에 얇은 "목 데이터 모드" 배너

### 처리 표기 (아래 표에서 사용)
| 표기 | 의미 |
|---|---|
| `읽기` | 목 데이터 표시 |
| `로컬` | 프론트에서 실제 동작 (검색·필터·정렬·페이지네이션) |
| `미구현` | 버튼만 배치 · 클릭 시 토스트 |

## 3. 공통 셸 · 라우팅

### 라우팅
- 기존 앱 안에 `/admin` 섹션 추가 (별도 앱 아님 — 혼자 프론트라 배포만 늘어남). `React.lazy`로 청크 분리
- `/admin`, `/admin/members`, `/admin/members/:id`, `/admin/posts`, `/admin/comments`,
  `/admin/articles`, `/admin/ads`, `/admin/ads/new`, `/admin/reports`, `/admin/settings`
- 임시 게이트: `AdminLayout`에서 `authStore`의 로그인 여부만 확인, 아니면 `/login`.
  실제 role 체크는 연동 시 한 줄 추가할 위치만 `TODO` 주석으로 남김

### 레이아웃
- 좌측 고정 사이드바(모듈 네비 + 현재 관리자 닉네임) + 우측 콘텐츠. 모바일은 상단 드로어
- 공통 컴포넌트: `DataTable`(정렬·선택·페이지네이션), `FilterBar`, `SearchInput`, `StatusPill`,
  `ConfirmModal`, `Toast`, `StubBadge`, `EmptyState`, `DetailDrawer`
- 외부 테이블 라이브러리 없이 자체 구현 (프로젝트가 가볍게 유지 중)

### 목 데이터
- `src/mocks/`: `members.json`, `posts.json`, `comments.json`, `articles.json`, `ads.json`,
  `reports.json`, `dashboard.json`
- 기사 목은 실제 `/api/news` 응답을 한 번 받아 캡처해서 쓰면 화면이 진짜처럼 나옴

## 6. 모듈 2 — 게시물 관리

게시글·댓글 모더레이션 화면.
**참고:** 실서비스 게시판 데이터는 아직 프론트도 더미(`dummyBoardPosts.js`)다. 관리 화면도 같은 더미를 확장한 목으로 만든다.

### 게시글 탭 `/admin/posts`

| 요소 | 내용 | 처리 |
|---|---|---|
| 테이블 컬럼 | 번호, 정당/게시판, 제목, 작성자, 작성일, 조회, 추천/비추천, 댓글수, 신고수, 상태(공개/블라인드/삭제) | `읽기` |
| 필터 | 정당, 게시판, 상태, "신고 있는 글만", 공지/일반, 기간 | `로컬` |
| 검색 | 제목·본문·작성자 | `로컬` |
| 블라인드 / 삭제 / 복원 | 행 액션 + 사유 입력 모달 → 토스트 | `미구현` |
| 공지 등록·해제 / 상단 고정 | 토글 → 화면만 변경, "새로고침 시 초기화" 표기 | `미구현` |
| 일괄 처리 | 체크박스 다중 선택 → 상단 액션 바 → 확인 모달 → 토스트 | `미구현` |
| 작성자로 이동 | 회원관리 상세로 링크 | `로컬` |

### 댓글 탭 `/admin/comments`
컬럼: 내용, 작성자, 소속 게시글(링크), 작성일, 신고수, 상태.
액션: 블라인드 / 삭제 / 작성자 이동 — 쓰기는 전부 `미구현`.

### 게시판 설정 탭
정당 5 × 게시판 5 카드 목록. 각 카드: 이름·설명·사용여부·글쓰기 로그인 필수·익명 허용 입력 필드.
"저장" → 토스트. (게시판 이름이 아직 "게시판1~5"라 확정 전이면 자리표시자로 둔다.)

## 8. 모듈 4 — 광고(AD) 관리

아직 광고 기능 자체가 없으므로 **화면 설계 우선**. 슬롯 → 소재 → 게재 일정 개념으로 구성.

### 소재 목록 `/admin/ads`

| 요소 | 내용 | 처리 |
|---|---|---|
| 테이블 컬럼 | 소재명, 광고주, 슬롯, 기간, 상태(예약/게재중/종료/중지), 노출수, 클릭수, CTR | `읽기` |
| 필터 | 슬롯, 상태, 기간 | `로컬` |
| 중지 / 재개 | 행 토글 → 토스트 | `미구현` |

### 소재 등록 `/admin/ads/new`
- 폼: 소재명, 광고주, 슬롯 선택, 이미지 업로드(데스크탑·모바일 각각 — 미리보기까지 로컬 구현),
  링크 URL, alt, 시작·종료일시, 가중치, 일 노출한도(선택)
- 슬롯 선택 시 우측에 **렌더 미리보기** (홈 상단 / 피드 네이티브 / 사이드 / 게시판 상단 / 상세 하단)
- "등록" → 확인 모달 → 토스트. 폼 유효성 검사는 프론트에서 실제로 동작

### 리포트 탭
기간 선택 + 슬롯별/소재별 노출·클릭·CTR 표와 막대 차트 (목 데이터).

> **화면에 넣어둘 것:** 소재 등록 폼에 "정치·후보자 광고 여부" 체크박스와, 체크 시
> "게재 전 승인 필요 · 선거기간 규제 대상" 안내 문구. 실제 승인 흐름은 백엔드 몫이지만 UI 자리는 지금 잡아둔다.

## 10. 프론트 구축 순서

1. **공통 셸** — `/admin` 라우팅, `AdminLayout` + 사이드 네비, 공통 컴포넌트(`DataTable`·`FilterBar`·
   `ConfirmModal`·`Toast`·`StubBadge`), `useStubAction`, 목 모드 배너.
2. **대시보드 홈 + 회원관리** — 지표 타일·미니 차트, 회원 목록/상세/제재 버튼.
   여기서 `DataTable` 패턴을 확정한다.
3. **기사관리** — 실제 `/api/news` 응답 캡처를 목으로. 분류 배지·필터·교정 드롭다운.
   나머지 모듈이 재활용할 목록 UI가 여기서 굳어짐.
4. **게시물 관리** — 게시글·댓글 탭, 일괄 처리, 게시판 설정 카드. (게시판 이름 확정되면 반영.)
5. **광고 관리 + 부가 화면** — 소재 목록·등록 폼·슬롯 미리보기·리포트 차트.

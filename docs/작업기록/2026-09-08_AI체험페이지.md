작성일: 2026-09-08
관련 모듈: `Team_Namoo_Front`(AiDemoPage, AiDevLog), `Team_Namoo_server`(news, classification)

---

## 1. 왜 만들었나

포트폴리오로 보여줄 때 **"AI 를 썼다"를 말로만 하지 않고 눌러보게** 하려고 만들었습니다.
기사를 넣고 버튼을 누르면 학습시킨 모델이 성향을 판정하고, 그 아래에 모델을 어떻게 만들었는지
개발 과정을 함께 보여줍니다.

주소는 `/ai`, 상단 네비바에 "AI 체험" 버튼으로 들어갑니다.

## 2. 화면 구성

**위: 판독기**

- 탭 두 개 — **본문 붙여넣기** / **기사 링크로**
- 본문 모드: textarea + 예시 버튼 3개(경제 정책 / 복지 정책 / 정치와 무관)
- 링크 모드: 주소를 넣으면 서버가 그 기사를 읽어와 본문을 뽑아 판정하고, 읽어온 제목도 함께 보여준다
- 결과: "AI는 이 기사를 **○○** 성향으로 판단했습니다" + 확신도 %, 성향별 색 카드

**아래: 개발 기록 (`AiDevLog.jsx`)**

일반인이 읽는다고 보고 전문용어를 쓰지 않았습니다.

1. 요약 카드 4개 — 정확도 68.1% / 학습 기사 17,696건 / 작업 기간 20일 / 개선 폭 30%→68%
2. **무엇으로 만들었나** — 기반 모델(klue/bert-base), 파인튜닝, PyTorch·Transformers,
   Apple M4·MPS, 학습 설정, 데이터 불균형 보정, FastAPI. 각 항목에 한 줄 설명을 붙였다
3. **날짜별 기록** — 3개 구간(콜랩으로 부딪히던 시기 / 직접 가르치기로 바꾼 시기 / 기준부터 다시 세운 시기)
4. **겪은 문제** — 실패한 시도를 그대로 남겼다
5. **라벨별 성적표** — 찾아낸 비율(재현율)과 맞춘 비율(정밀도)을 나란히
6. 맺음말

### 라벨별 성적표를 표로 만든 이유

처음에는 "보수를 가장 못 잡습니다(32건 중 15건)" 라고 문장으로 적었는데,
그러면 **47% 라는 숫자만 도드라져 보입니다.** 네 라벨을 표로 나란히 놓으면 읽는 사람이
판단불가 100% 를 먼저 보고, 보수 47% 옆의 정밀도 75% 를 함께 봅니다.
"못 만든 모델" 이 아니라 **"소극적인 모델"** 로 읽히고, 면접에서 "보수가 왜 낮나요?" 가
불리한 질문이 아니라 준비된 질문이 됩니다.

| 성향 | 찾아낸 비율 | 맞춘 비율 |
|---|---|---|
| 진보 | 66% (32건 중 21건) | 75% |
| 중립 | 65% (26건 중 17건) | 52% |
| 보수 | 47% (32건 중 15건) | 75% |
| 판단불가 | 100% (26건 중 26건) | 74% |

수치는 `namoo-classifier-train/docs/결과/전체학습결과.json` 의 실제 값입니다.

## 3. 서버에서 한 일

**새 엔드포인트를 만들지 않고 기존 `POST /api/news/classify` 를 확장했습니다.**
같은 일을 하는 API 가 둘이 되는 것을 피하기 위해서입니다.

| 변경 | 내용 |
|---|---|
| `ClassificationResult` (신규) | 라벨 + 확신도를 함께 담는 record |
| `ClassificationModelClient.classifyWithConfidence()` | 모델 응답의 `확신도` 를 버리지 않고 함께 반환. 기존 `classify()` 는 이 메서드를 부르도록 정리 |
| `ClassifyRequest` | `url` 필드 추가. 주면 그 주소의 기사를 읽어와 분류한다 |
| `ClassifyResponse` | `confidence`(0~100), `title`(읽어온 기사 제목), `message`(실패 사유) 추가 |

링크 모드는 기존 `ArticleTextExtractor` 를 그대로 씁니다.

### SSRF 방어 (중요)

**사용자가 준 주소를 서버가 대신 열어보는 구조**라, 막지 않으면 사내망이나
AWS 메타데이터 주소(`169.254.169.254`)를 찔러 서버 자격증명이 새어나갈 수 있습니다.
`assertFetchableUrl()` 에서 다음을 거부합니다.

- http/https 가 아닌 스킴 (`file://` 등)
- 호스트가 루프백·링크로컬·사설망·멀티캐스트로 풀리는 주소

검증: `169.254.169.254`, `localhost:8080`, `127.0.0.1:8000`, `192.168.0.1`, `file:///etc/passwd`
모두 차단 확인.

## 4. 검증

로컬에서 프론트(5173) + 백엔드(8080) + 분류 서버(8000)를 모두 띄우고 확인했습니다.

| 항목 | 결과 |
|---|---|
| 본문 모드 | `{"leaning":"중립","confidence":58}` |
| 링크 모드 | `{"leaning":"중립","confidence":46,"title":"인천시선관위, …"}` 실제 기사 크롤링 성공 |
| SSRF 5종 | 전부 차단 |
| lint / build | 무경고 / 성공 |

브라우저 화면 확인은 사용자가 직접 했습니다.

## 5. 배포 시 주의 ★

**프론트만 배포하면 이 페이지가 깨집니다.** 프론트가 `confidence` 와 `url` 을 쓰는데
백엔드가 예전 코드면 `confidence` 가 없어서 "확신도 undefined%" 가 뜨고 링크 모드가 동작하지 않습니다.
**백엔드(EC2) jar 을 반드시 함께 배포해야 합니다.** (같은 실수를 9/8 오전에 이미 한 번 했습니다 —
`RULES.txt` 오답노트 5번)

그리고 **운영에 붙어 있는 분류 모델이 아직 29% 짜리입니다.** 체험 페이지를 외부에 공개하려면
`docs/AI_MODEL_HANDOFF.md` 의 모델 교체를 먼저 해야 합니다. 그러지 않으면 무엇을 넣어도
"진보 31~36%" 같은 답이 나옵니다.

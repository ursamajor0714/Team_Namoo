--------------------------------------------------------------------
1. 전체 그림 - 누가 뭘 어디에
--------------------------------------------------------------------

계정 2개로 나눠서 올린다. (프리티어를 각자 따로 쓰려고)

리전은 둘 다 "서울(ap-northeast-2)"로 통일한다. (한국 사용자 응답 빠름.
규칙은 나랑 팀원이 같은 리전을 쓰는 것.)

올리는 위치 요약:
  프론트(React)   -> Amplify Hosting  (GitHub 연결, push 자동배포. 서버 안 만듦)
  백엔드(Spring)  -> EC2 t3.micro 1대  (직접 서버 만들어서 jar 실행)
  DB(MySQL)       -> RDS  (RDS 콘솔에서 인스턴스 생성. 서버 안 만듦)
  모델(classify)  -> 팀원 계정 EC2 t3.micro 1대 + 스왑

[내 계정]  (ursamajor, 909643315363, 리전: 서울 ap-northeast-2)
  - Amplify   : 프론트(Team_Namoo_Front)
  - EC2 1대   : 백엔드(Spring Boot)
  - RDS 1대   : MySQL (DB)

[팀원 계정]  (리전: 나랑 똑같이 서울)
  - EC2 1대   : classification-api (모델) 전용 + 스왑 메모리

연결 방식:
  내 Spring이 팀원 EC2로 "인터넷 전화"를 건다.
  Spring 설정 classification.model.base-url 값을
  http://localhost:8000  ->  http://<팀원-EC2-고정주소>:8000  으로 변경.
  계정이 달라도 상관없음. 주소만 알면 됨.


--------------------------------------------------------------------
2. 왜 이렇게 나눴나
--------------------------------------------------------------------

- 프리티어 EC2 = t3.micro = 램 1GB. 여기에 다 못 올림.
    Spring(0.5~1GB) + PyTorch 모델(1.5~2GB) + MySQL(0.3GB) => 1GB 초과
- 모델(PyTorch + 423MB BERT)이 제일 무거움 -> 팀원 EC2에 통째로 격리
- DB는 EC2에 같이 넣으면 램 빡빡 -> RDS로 분리 (프리티어 따로 잡힘)
- 남은 내 EC2에는 Spring만 -> 1GB로 여유 있음


--------------------------------------------------------------------
3. 무료(프리티어) 유지 규칙
--------------------------------------------------------------------

- 프리티어 한도는 항목별로 따로따로다:
    EC2  : t3.micro 750시간/월  (= 1대를 24시간 켜두면 딱 맞음, 744h < 750h)
    RDS  : db.t3.micro 750시간/월  (EC2와 별개로 또 750시간)
  => 내 EC2 + 내 RDS 둘 다 24시간 켜놔도 각각 무료 범위 안.
  => 팀원 EC2도 팀원 계정 몫 750시간이 따로 있음.

- 프리티어는 "계정 만든 날부터 12개월" 한정. 영구 무료 아님.
  (최근 만든 계정은 크레딧 방식일 수 있으니 결제 페이지에서 확인)

- EC2는 Render처럼 안 잠든다. 한번 켜면 직접 끄기 전까지 24시간 돈다.
  핑 작업 필요 없음.

- 고정 주소(Elastic IP) 요금 주의:
    만들자마자 "켜져 있는 서버에 연결"하면 무료.
    만들어놓고 방치(연결 안 함 / 연결한 서버가 꺼짐)하면 매달 ~$3~4 청구.
    => Elastic IP 할당하면 곧바로 서버에 붙일 것.


--------------------------------------------------------------------
4. 결정된 것
--------------------------------------------------------------------

  - 도메인 안 씀
  - 커스텀 TLS 인증서 설정 안 함
  - 계정 2개로 분리 (내: 프론트+백, 팀원: 모델)
  - DB는 RDS로 분리
  - 프론트는 Amplify Hosting (GitHub 연결 자동배포)
  - 리전: 둘 다 서울(ap-northeast-2)
  - 프리티어만 사용
  - EC2는 내 것도 팀원 것도 t3.micro 고정. 스펙업(유료) 안 함.
    모델 콜드스타트가 느린 건 감수한다.


--------------------------------------------------------------------
5. 작업 순서 (전체 흐름)
--------------------------------------------------------------------

배포는 "도커 이미지를 로컬에서 굽고 -> Docker Hub에 올리고 -> EC2에서
받아 실행" 방식이다. 세부 명령/설정은 5-1(계정·콘솔 설정), 5-2(도커 절차)
참고. 아래는 큰 순서만.

  0) [1회성] 계정 초기 설정 - 루트 MFA, 일상용 IAM 사용자, 결제 경보/예산,
     리전을 서울로 고정                              -> 5-1
  1) 로컬에서 Spring 이미지 빌드(--platform linux/amd64) + 로컬 실행 테스트
     -> Docker Hub push                              -> 5-2 1~2단계
  2) 내 계정: RDS MySQL(프리티어) 생성, 접속정보 메모  -> 5-2 3단계
  3) 내 계정: EC2(t3.micro) 생성 + Elastic IP 연결 +
     도커 설치 + 이미지 pull + .env 넣고 run          -> 5-2 4단계
  4) RDS 보안그룹에 EC2 허용, Spring이 DB 붙는지 확인
  5) 팀원 계정: EC2 + swap + classifier 이미지 run +
     Elastic IP + 8000 포트를 내 EC2만 허용           -> 5-2 5단계
  6) Spring .env 의 분류서버 주소를 팀원 EC2로 -> 재실행 -> 5-2 6단계
  7) 프론트: Amplify에 GitHub 연결(모노레포, 루트=Team_Namoo_Front),
     API 주소 env 를 내 EC2 로                        -> 5-2 6~7단계
  8) 회원가입/로그인/뉴스/분류/게시판 end-to-end 검증  -> 5-2 8단계

** 백엔드 담당 몫: classification-api Dockerfile, Spring .env 항목 구성,
   actuator 헬스체크. 나는 그 외 콘솔 작업 + 프론트. **


--------------------------------------------------------------------
5-1. AWS 계정 / 콘솔 설정 상세  (계정은 이미 만들어져 있음)
--------------------------------------------------------------------

[A] 루트 계정 보안 (지금 바로)
  - 콘솔 우상단 계정명 > 보안 자격 증명 > MFA 등록
      (휴대폰 Authenticator 앱으로. 루트는 청구/계정폐쇄 권한이라 필수)
  - 루트 액세스 키가 있으면 삭제. 루트로는 평소 작업 안 함.

[B] 일상 작업용 IAM 사용자 (권장, 건너뛰어도 진행은 됨)
  - IAM > 사용자 > 생성 > 콘솔 액세스 허용
  - 권한: 우선 AdministratorAccess 붙여서 시작 (학습용)
  - 이 사용자로 다시 로그인해서 이후 작업 진행
  - 팀원도 각자 자기 계정에서 동일하게

[C] 요금 방어막 (가장 중요, 지금 바로)
  - 결제 및 비용 관리 > 결제 기본 설정
      "프리 티어 사용량 알림 받기" 체크 + 이메일 입력
  - CloudWatch > 경보 > 결제 경보 생성
      지표: 예상 요금(Total), 임계값 $1 초과 시 이메일
      (결제 지표는 버지니아 북부 us-east-1 에서만 보임 - 경보도 거기서 생성)
  - AWS Budgets > 예산 생성 > 월간 비용 예산 $5, 80%/100% 알림
  - 목적: 프리티어 밖으로 새는 순간(EIP 방치, 스토리지 초과 등) 바로 알람

[D] 리전 고정
  - 콘솔 우상단에서 "아시아 태평양(서울) ap-northeast-2" 선택
  - 이후 모든 작업(EC2/RDS/Amplify)을 이 리전에서. 리전 다르면 서로 안 보임.
  - 예외: 위 [C]의 결제 경보만 us-east-1

[E] 네트워크 (새로 만들 것 없음)
  - 계정에 기본 VPC + 기본 서브넷이 이미 있음. 그거 그대로 사용.
  - VPC/서브넷/인터넷게이트웨이 직접 만들지 말 것 (이번 규모엔 불필요)

[F] 보안그룹 (방화벽) - 총 3개 만든다
  sg-ec2-spring  (내 EC2)
     인바운드:  22/tcp   <- 내 집 IP/32              (SSH)
               8080/tcp <- 0.0.0.0/0                (프론트/브라우저가 호출)
     아웃바운드: 전체 허용 (기본값)
  sg-rds-mysql   (내 RDS)
     인바운드:  3306/tcp <- sg-ec2-spring            (EC2에서만 DB 접근)
     퍼블릭 액세스: 아니오
  sg-ec2-model   (팀원 EC2, 팀원이 생성)
     인바운드:  22/tcp   <- 팀원 집 IP/32
               8000/tcp <- 내 EC2 Elastic IP/32     (내 Spring만 호출)
  * "내 집 IP"는 https://checkip.amazonaws.com 에서 확인. 집 IP 바뀌면
    규칙도 갱신해야 함.

[G] 키페어
  - EC2 > 키 페어 > 생성 > .pem 다운로드 (RSA, .pem)
  - 로컬에서  chmod 400 team-namoo.pem
  - 분실하면 그 인스턴스엔 다시 SSH 못 붙음 -> 잘 보관

[H] Amplify <-> GitHub
  - Amplify 앱 만들 때 GitHub 로그인/권한 승인 창이 뜸 -> 레포 접근 허용
  - 그 외 IAM 설정 따로 없음 (Amplify가 알아서 역할 생성)


--------------------------------------------------------------------
5-2. 도커(Docker) 기반 배포 상세 절차
--------------------------------------------------------------------

방식: 로컬(내 맥, OrbStack 사용)에서 이미지를 빌드해서 Docker Hub에
push -> EC2에서 pull -> 실행. t3.micro(1GB)에서 직접 빌드하면 램 부족으로
느리거나 죽어서, 빌드는 로컬에서 한다.
(Docker Hub 계정 만들기 싫으면 대안: 로컬에서 `docker save`로 tar 만들어
 scp로 EC2에 올리고 `docker load`. 레지스트리 불필요, 대신 수동.)

--- 0단계: 준비 (로컬) ---
  - OrbStack 실행 중이면 docker 명령 그대로 됨 (별도 설치 불필요)
  - Docker Hub 무료 계정 생성 (개인 private repo 1개 무료)
  - classification-api 용 Dockerfile 작성  ** 백엔드 담당 **
      (Spring은 Team_Namoo_server/Dockerfile 이미 있음)
      python:3.12-slim 베이스, requirements.txt 설치, 8000 포트,
      CMD uvicorn main:app --host 0.0.0.0 --port 8000
  - 모델 파일(model/latest, 약 444MB)은 이미지에 굽지 말고 볼륨 마운트로.
      main.py가 MODEL_DIR 환경변수로 경로를 받으므로
      docker run 시 -v /home/ec2-user/model:/app/model -e MODEL_DIR=/app/model

--- 1단계: 로컬에서 이미지 빌드 + 테스트 ---
  * 맥은 Apple Silicon(arm64), EC2 t3.micro는 x86_64(amd64)라
    반드시 --platform linux/amd64 를 붙여서 빌드해야 EC2에서 돌아감.
  docker build --platform linux/amd64 \
    -t <dockerhub아이디>/namoo-server ./Team_Namoo_server
  docker run --rm -p 8080:8080 --env-file .env.local <...>/namoo-server
    -> localhost:8080 뜨는지 확인 후 종료
    (arm 맥에서 amd64 이미지는 에뮬레이션으로 돌아 좀 느림. 정상.)
  (classifier도 팀원이 같은 방식으로, --platform linux/amd64 붙여서)

  도커 런타임은 맥에 이미 깔린 OrbStack 사용 (Docker Desktop 불필요).
  OrbStack 앱만 켜져 있으면 docker 명령 그대로 동작.

--- 2단계: Docker Hub에 push ---
  docker login
  docker push <dockerhub아이디>/namoo-server
  (classifier는 팀원이 자기 계정으로 push)

--- 3단계: 내 AWS - RDS (MySQL) ---
  RDS > 데이터베이스 생성:
    - 엔진: MySQL,  템플릿: "프리 티어"
    - DB 인스턴스 식별자: namoo-db
    - 마스터 사용자명: admin / 마스터 암호: (생성해서 메모)
    - 인스턴스 클래스: db.t3.micro  (프리티어에서 자동 선택됨)
    - 스토리지: 20GB gp3,  "스토리지 자동 조정" 체크 해제 (요금 방지)
    - 연결: 기본 VPC,  퍼블릭 액세스 "아니오"
            VPC 보안그룹 = 새로 생성 -> 이름 sg-rds-mysql
    - 다중 AZ 배포: 아니오 (프리티어 아님)
    - 추가 구성 > 초기 데이터베이스 이름: teamnamoo
    - 자동 백업: 7일 (기본), 삭제 방지 켜두면 편함
  생성 완료 후:
    - "엔드포인트" 주소 메모 (예: namoo-db.xxxx.ap-northeast-2.rds.amazonaws.com)
    - 포트 3306
  ** 이 시점엔 아직 EC2가 없어서 sg-rds-mysql 인바운드는 비워둠.
     4단계에서 EC2 만들고 나서 규칙 추가. **

--- 4단계: 내 AWS - EC2 (Spring) ---
  EC2 > 인스턴스 시작:
    - 이름: namoo-spring
    - AMI: Amazon Linux 2023 (x86_64)
    - 인스턴스 유형: t3.micro  ("프리 티어 사용 가능" 표시 확인)
    - 키 페어: 5-1 [G]에서 만든 team-namoo 선택
    - 네트워크: 기본 VPC / 기본 서브넷,  퍼블릭 IP 자동 할당 "활성화"
    - 보안그룹: 새로 생성 -> sg-ec2-spring
        22   <- 내 집 IP/32
        8080 <- 0.0.0.0/0
    - 스토리지: 30GB gp3  (프리티어 30GB까지 무료)
  시작 후:
    - EC2 > 탄력적 IP > 할당 -> 즉시 이 인스턴스에 "연결"
    - RDS 보안그룹(sg-rds-mysql) 인바운드에
        3306 <- sg-ec2-spring  규칙 추가
  SSH 접속 (ssh -i team-namoo.pem ec2-user@<Elastic IP>) 후:
      sudo dnf install -y docker
      sudo systemctl enable --now docker
      sudo usermod -aG docker ec2-user      # 로그아웃 후 재접속
      docker pull <dockerhub아이디>/namoo-server
  .env 파일 작성 (RDS 엔드포인트/DB이름/계정/비번, NAVER/OpenAI/Claude 키.
      분류서버 주소는 6단계 후 채움)              ** 백엔드 담당 **
      docker run -d --restart unless-stopped -p 8080:8080 \
        --env-file .env <dockerhub아이디>/namoo-server
  확인:
      docker logs -f <컨테이너>       # 부팅 로그, DB 연결 성공 보기
      curl localhost:8080/actuator/health   (actuator 엔드포인트 ** 백엔드 **)

--- 5단계: 팀원 AWS - EC2 (classifier) ---
  - EC2 t3.micro, 서울, 키페어, 보안그룹 22(팀원 IP)
  - swap 4GB 추가:
      sudo fallocate -l 4G /swapfile && sudo chmod 600 /swapfile
      sudo mkswap /swapfile && sudo swapon /swapfile
      echo '/swapfile none swap sw 0 0' | sudo tee -a /etc/fstab
  - docker 설치 (4단계와 동일)
  - 모델 파일을 EC2로 전송:
      로컬에서  scp -i key.pem -r classification-api/model/latest \
                ec2-user@<팀원EC2>:/home/ec2-user/model
  - docker pull <팀원dockerhub>/namoo-model
  - docker run -d --restart unless-stopped -p 8000:8000 \
      -v /home/ec2-user/model:/app/model -e MODEL_DIR=/app/model \
      <팀원dockerhub>/namoo-model
  - Elastic IP 할당 -> 즉시 연결
  - 보안그룹 인바운드 8000: 소스를 "내 Spring EC2의 Elastic IP/32" 로만 허용
  - 팀원이 이 Elastic IP를 나한테 알려줌

--- 6단계: 연결 ---
  - 내 EC2 .env 의 classification.model.base-url =
      http://<팀원EC2 Elastic IP>:8000
    수정 후  docker rm -f  하고  docker run 다시
  - 프론트(Amplify) 환경변수 VITE_API_BASE_URL = http://<내 EC2 Elastic IP>:8080
      ** 프론트 코드에서 하드코딩된 localhost:8080 을 이 env 로 교체 (내 담당) **

--- 7단계: 프론트 (Amplify) ---
  * 프론트는 도커 안 씀. 맞음.
    Amplify가 알아서 레포 받아서 npm run build 돌리고, 결과 정적파일(dist)을
    CDN에 올려서 서빙함. 도커는 EC2에서 직접 프로세스를 띄워야 하는
    Spring/classifier 에만 필요. 정적 사이트엔 컨테이너가 필요 없음.
  - Amplify > 앱 생성 > GitHub > Team_Namoo / front 브랜치
  - "모노레포입니다" 체크, 앱 루트 = Team_Namoo_Front
  - 빌드 설정: npm run build,  출력 디렉터리: dist
  - 환경변수 VITE_API_BASE_URL = http://<내 EC2 Elastic IP>:8080

--- 8단계: 전체 검증 ---
  회원가입 -> 로그인(새로고침해도 세션 유지) -> 뉴스 목록 -> 기사 분류
  -> 게시판 목록/작성/댓글. "떴다"가 아니라 실제 동작까지 확인.

--- 재배포 (나중에 코드 고쳤을 때) ---
  로컬:  docker build ... && docker push ...
  EC2 :  docker pull ... && docker rm -f <컨테이너> && docker run ...
  (이 3~4줄을 GitHub Actions로 자동화하는 건 나중 단계)

6. 주의점 ("올라갔다" != "된다")
--------------------------------------------------------------------

- NAVER 뉴스 API 일별 쿼터 있음 -> 배포 직후 429 뜨면 고장 아니라 쿼터임
- classifier는 model/latest 파일(423MB, gitignore됨)이 실제로 있어야 동작
- 모델 콜드스타트: PyTorch + 423MB 로드에 20~40초 (스왑이면 더)
- 세션 로그인: 프론트/백 주소가 다르면 쿠키 문제 생길 수 있음
    (같은 주소로 /api 라우팅하면 회피되지만 이번엔 도메인 안 쓰기로 함)
- 팀원 EC2가 꺼지면 내 분류 기능도 멈춤 -> 둘 다 켜놓기로 합의
- application.properties 에 NAVER 키가 평문 커밋됨 + git 히스토리에 남음
    -> 백엔드 담당이 키 로테이션 필요 (보안)
